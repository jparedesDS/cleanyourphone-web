How it works

Three steps. You stay in control.

  1. 01

    Connect

    Enable USB debugging, connect the phone and run doctor. It checks ADB, the device, the backup and the profile match before anything changes.

  2. 02

    Review

    The CLI backs up packages, roles and settings, then shows a plan with why and breaks for every package. Nothing changes yet.

  3. 03

    Disable

    Packages are disabled in batches of five, followed by verification. restore undoes the exact changes; restore --from-backup is the fallback if the journal is lost.

The CLI is optional. SKILL.md contains the raw ADB procedure for an agent that cannot run Python.

The CLI

A guided command set.

Python 3.10+. No packages. wizard is the simple path; plan and apply are there when you want control.

doctor

Checks ADB, the phone, the backup and the profile match.

wizard

Guided flow: backup, profile choice, per-package review and apply.

plan

Shows DISABLE, ASK, BLOCKED and SKIP without changing anything.

apply

Applies a tested device profile's disable list in batches of five.

restore

Re-enables exactly what the tool disabled and restores Private DNS.

restore --from-backup

If the journal is lost, reconstructs the change from the backup. Dry run until --yes.

verify

Checks dialer, SMS, Home, keyboard, Play and protected packages.

profiles

Lists the 156 model/firmware profiles and their verification level.

protected

Shows the packages that are never touched.

validate

Validates every profile in the catalog.

Installed as cleanyourphone and cyp; the repo-local form is python tools/phone.py.

Safety

Safe by design. Boring on purpose.

Disable, never uninstall

Only pm disable-user --user 0. No uninstall, hide, clear or root. pm enable is the undo.

Back up first

Packages, roles, IME, settings and getprop are saved before the first change. No backup, no changes.

Protected list and roles

Telephony, Play Services, WebView, permissions, emergency alerts, dialer, SMS, Home and keyboard are refused or checked.

Small batches, clear undo

Five packages, verify, then the next batch. The journal is exact; if it is lost, the backup reconstructs the change.

A wrong core package can cause a boot loop. Read the recovery guide ↗

FAQ

Short answers.

Is it safe?

Safer than a copied package list, but not magic. It never uninstalls, backs up first, refuses protected packages and role holders, disables in small batches and can undo every change. You still review the plan and test calls, SMS, camera, keyboard, Home and notifications.

Does it uninstall anything?

No. The only state change is pm disable-user --user 0. No uninstall, hide, clear or root. pm enable is the undo.

What if something goes wrong?

Stop. Run restore if ADB still sees the phone. If the undo journal is lost, run restore --from-backup <folder> and review the list. If the phone does not boot, the recovery guide covers safe mode, ADB and recovery; factory reset is the last resort.

Does it work on tablets?

Yes, on Android 8+ with ADB. Tablet profiles set form_factor: tablet; a missing dialer or SMS role is a warning, not a failure. Home and keyboard checks still apply.

Do I need Python?

No. SKILL.md contains the raw ADB procedure. If you use the CLI, Python 3.10+ and Platform-Tools are enough; there are no third-party dependencies.

Is it free?

Yes. MIT license. No account, no subscription, no telemetry and no hosted service.
